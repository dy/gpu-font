# Experimental Google Fonts encoder

This is the shared encoder currently used by the demo. The [recovery comparison](../../bench/encoder-quality.md) selects a compact cross-text refinement with script-separated references. It improves the baseline but has not met the retrieval or rejection gates.

- `encoder.json`: 349,920 training parameters, packed int8 tensors (489,085 bytes), 128-dimensional L2-normalized output, no font labels. SHA-256 `39633bd246fa0b47ee91ebbe8eb09faa709611427d3cf311767b150b16f4ab5c`.
- `google-fonts.json`: 2,004 eligible Google Fonts families, one selected normal face each and 3,492 int8 references separated by script. Version 3 uses explicit vector owners. Exact encoder/preparation hashes prevent mixing incompatible catalogs. Weight/style fields describe the source face; they are not calibrated attribute predictions.
- `best.pt`: selected floating-point PyTorch checkpoint for reproducibility, excluded from browser payload.

The original encoder was trained from scratch on 1,403 families and selected using 301 development families. This continuation initializes from its 20,000-step checkpoint and selects 10,000 additional cross-text updates. No final-family query enters optimization or recovery selection. The eight reported train/development-family demo examples now explicitly participate in recovery selection; final-family reference images supply catalog distractors. Adding families still requires indexing only. The classification head used during training is discarded.

Prepare tight grayscale windows with the exact hashed `deskew-windows` preparation in the encoder, preserving aspect ratio and at most 128×48 pixels per window. Normalize each projection, average all windows from the source, then normalize again. References use different strings from queries. Rebuild catalogs whenever encoder or preparation changes.

See [recovery selection](../../bench/encoder-recovery-selection.json) and [confirmation](../../bench/encoder-recovery-quality.json) for exact hashes and results. Reproduce confirmation/catalog generation with `node scripts/python.mjs -m train.encoder_case_quality --recovery` after preparing the pinned datasets. Verify CPU/Metal parity with `node checks/encoder.mjs`. The demo loads source catalogs through `src/catalog.mjs`, checks encoder/preparation bindings, and searches their reference vectors using the shared encoder. The package is not yet published. The original baseline remains in Git history and `.data/encoder/classification/`.

On historical final queries, unseen-family top-1/top-5 is 39.59%/63.06% (macro top-5 63.91%). On the fresh 1,356-crop phrase confirmation, top-1/top-5 improves from 21.24%/37.61% to 24.41%/45.72%. The reported Lora sample ranks first with a narrow cosine margin; Montserrat still ranks twelfth. No rejection threshold or certainty percentage is calibrated for this encoder/catalog. Model, Google catalog and required modules total 1,723,636 bytes before HTTP compression; optional display fonts/images are separate.
